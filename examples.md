# Strong vs weak examples

Anonymized contrasts for each success pattern. Use when scoring a brief or teaching the bar.

---

## 1. Frame the mission and the number (Charter)

**Strong**
“Help new customers complete foundational setup via AI-guided + human-assisted paths. North star: assisted setup rate 12% → 30%. Each incremental successful setup is worth ~$X. Candidate surfaces: Setup Hub, onboarding checklist, contact entry — provisional.”

**Weak**
“Improve onboarding. Build a better setup checklist and maybe an AI agent.”

---

## 2. Ground the problem in research (Research-based problem)

**Strong**
Quotes from 8 interviews on “I don’t know what to ask an expert yet,” funnel showing high schedule-then-miss rates, prior study: assisted completers far more likely to finish core jobs. Problem framed from that pack.

**Weak**
“Stakeholders feel onboarding is confusing. Leadership wants AI.”

---

## 3. Prove the problem before designing (Problem stack)

**Strong**
Full stack ending in mad-libs + primary hypothesis: “Users don’t engage experts because prompts aren’t timed to stuck moments and the call feels too high-commitment.”

**Weak**
“Users struggle with setup” → immediately “so we’ll add a chatbot.”

---

## 4. Map the path to the action (Decision funnel)

**Strong**
Awareness → Interest → Decision → Action with data on each; primary attack = Decision (scheduling commitment). Workshop brief says “no Awareness-only ideas.”

**Weak**
Journey map poster with no drop-off pick; solutions scattered across all stages.

---

## 5. Name the human behavior mechanics (Fogg)

**Strong**
Target behavior: engage expert help at Decision stage. Motivation high; Ability low (45–60 min call); Prompt weak (generic tile). Bets explicitly raise Ability + Prompt.

**Weak**
“Make the expert offer more prominent” with no MAP diagnosis (often a Prompt-only fix when Ability is the real blocker).

---

## 6. Steal clarity from analogs (Analog research)

**Strong**
Canva/Duolingo for self-serve pathway (steal progressive prompts; reject gamification noise). Superhuman/HubSpot for human-led pathway (steal structured first session; reject mandatory long setup for all). Each tied to MAP levers.

**Weak**
“Looked at Competitor X’s settings page” or a mood board with no steal/reject.

---

## 7. Workshop ideas as a team (Collaborative ideation)

**Strong**
Cross-functional session with funnel + MAP + analogs as inputs; clusters by lever; surfaces emerge: in-context abandonment prompt, durable agentic expert step. Shortlist of 3.

**Weak**
PM writes a backlog alone; “workshop” is a slide review of already-chosen UI.

---

## 8. Paint the destination, then pick a few bets (Vision + Big Bets)

**Strong**
Vision: expert-led platform onboarding. Four pillars. Surfaces locked. Each bet maps to a MAP lever and funnel stage.

**Weak**
Vision paragraph + 20-item roadmap called “bets.”

---

## 9. Ask what each metric will teach us (Metrics as questions)

**Strong**
“Does in-context prompt increase expert contact rate without hurting TNPS?” Learning: “Do users understand AI vs expert?”

**Weak**
“Track clicks, DAU, NPS” with no decision each metric unlocks.

---

## 10. Break strategy into testable bets (Nested experiment PRDs)

**Strong**
Child PRD: provocation, LOFA, hypothesis, requirements, risks, alignment to Big Bet “surface help in context.”

**Weak**
Strategy doc only; eng asked to “figure out an MVP.”

---

## 11. Define when we graduate (Graduation criteria)

**Strong**
Pilot with N users / ring-fenced experts → graduate to A/B if contact rate ≥ X and quality ≥ Y; else revise toward async.

**Weak**
“Ship widely and monitor.”

---

## 12. Design for different people differently (Personas as pathways)

**Strong**
Nellie path = guided self-serve/AI. Marvin path = human-led. Go-wide explores both modes before converging.

**Weak**
One persona poster; one UI for everyone.

---

## 13. Go wide, then narrow — repeatedly (Iterative design)

**Strong**
Three directions → critique → two prototypes → usability → second wide/narrow on handoff clarity → decision-ready.

**Weak**
One high-fidelity mock approved in a review with no usability; no alternate directions.

---

## Composite brief: Guided Setup Agent (smoke reference)

When assessing a case like “AI assisted onboarding: Guided setup agent,” expect partial credit across:

| Pattern | Typical score if case is design-forward |
|---------|----------------------------------------|
| Charter / north star | Partial–Strong if rates and vision present |
| Research-based problem | Strong if problem + quotes/data present |
| Problem stack / mad-libs | Strong if mad-libs present |
| Decision funnel | Partial unless stages/drop-offs explicit |
| Fogg MAP | Partial unless M/A/P named |
| Analogs | Missing–Partial unless outside products cited |
| Workshop / surfaces | Partial if surfaces implied in product story |
| Vision + Big Bets | Partial if vision present without pillars |
| Metrics as questions | Partial if metrics listed without questions |
| Experiment PRD / LOFA | Partial–Strong if hypothesis/test framing exists |
| Graduation criteria | Often Missing |
| Personas as pathways | Strong if persona + goals shown |
| Iterative design loop | Partial–Strong if MVP → learnings → iteration shown |

Use this as a calibration sample, not a perfect gold score.
